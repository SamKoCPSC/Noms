# Settings and public-profile explorations v1

Date: 2026-09-13. Ten desktop-only directions generated with the built-in image generation tool. Phone and tablet design work is deferred at the user's request, not removed from eventual responsive scope. Each board pairs private owner Settings (left) with public viewer Profile (right). P1 and P8 are the preferred directions; no app code changed.

## Preferred directions — 2026-09-13

The user selected **P1 Kitchen Passport** and **P8 Cozy Accordion** as the preferred Settings/Profile references. Retain P1's clear identity/form cards and content hierarchy alongside exploration of P8's rounded disclosure groups. The precise combination, disclosure defaults, and whether public content sections collapse remain to be refined; neither board is a final behavior specification. Preserve N1/N4 shared navigation, C3 collection imagery, existing account safeguards and the separation of private settings from public profile content. Desktop refinements come next; phone/tablet remain deferred. Other boards are exploration history.

Canonical decision: [NOMS-020 implementation plan](../../implementation-plans/NOMS-020-visual-design-refinement.md).

## Design context and boundaries

Retain selected N1/N4 shared navigation and C3 Kitchen Albums collection imagery. Warm cream, sage/olive, coral, Fredoka display and Nunito body, with restrained neumorphism. Generated typography, A3 logos and copy are approximations, not production assets. Source grounding: src/pages/settings/settings_profile.rs, settings_accounts.rs and src/pages/user_profile.rs. Actual fields include avatar, display name, username and bio; linked accounts support Google/GitHub and require at least one sign-in method. Public profiles show public collections and recipes.

Alternative grouping, local tabs, accordion sections and live previews are proposals, not authorization to change behavior. Private email and account controls must never leak onto public profiles. Generated deletion copy is not authoritative: retain existing confirmation and deletion-impact behavior. Unlinking must preserve a remaining sign-in method. Exact provider branding, avatar tools, limits/validation, focus/contrast and action states need refinement. No social follows, messages, ratings or new preference features are implied. Any illustrative cover collage must derive only from public content, not imply a new uploaded cover feature.

## Remaining desktop states

Visual QA: all ten boards render Settings and public Profile side by side. P2 shows both tab sections simultaneously and needs explicit tab-versus-anchor behavior; P3's Google “Change” is not an approved provider operation; P4 drifts toward non-Fredoka type; P5's public layout remains a grid despite the row-based prompt; P6 tilts the identity text and places Save below unrelated account actions, both to correct before implementation. Several boards omit avatar Edit photo or detailed provider unlink controls; these existing actions must remain available. Slogans, sample emails, identities, counts and timings are illustrative. N1/N4 navigation needs exact shared-component sizing, and text/contrast need implementation validation.

Avatar choose/edit/crop/remove, field validation, unsaved/save/loading/error feedback, provider linking failure and unlink confirmation, account deletion confirmation, missing/empty/public profile states and pagination. Dark mode remains to be explored. Responsive work is explicitly deferred for now.
